Trecho literal (verbatim via WebFetch 2026-10-04):
"An event store is an append-only log of domain events... the database contains the event log,
not the current state rows."
"A projection consumes the event stream and builds a read-optimized view... Multiple projections
can consume the same event stream for different purposes."

Contexto secundario (WebSearch 2026-10-04, DADO):
"Consumers can subscribe to streams and receive events in real time ... catch-up subscriptions
(replay from any point) and persistent subscriptions (competing consumers)."
"The last event processed by the event handler (subscription) is stored in the separate table
ES_EVENT_SUBSCRIPTION. New events are processed by polling the ES_EVENT table."

Papel no Dossie: fundamenta "multiplos consumidores projetam/reagem sobre o mesmo log
append-only via cursor de leitura (catch-up subscription)" — modelo compativel com RULE-BB-004/
INV-07 e com o replay ja entregue pela SPEC-004.
